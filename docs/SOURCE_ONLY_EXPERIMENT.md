# 3D-ACDA Source-Only Experiment

## Scientific role

**3D-ACDA Source-Only** is the no-domain-adaptation comparison. It uses the
same explicit 3D-ACDA architecture and source-supervised core losses that
later adaptation experiments will use, but has no adaptation loss or target
training operation.

Supported directions are ADNI to OASIS and OASIS to ADNI. Each direction uses
the immutable Phase 6 `source_folds.csv`, with folds 0 through 4, and the fixed
`target_evaluation` rows from `target_split.csv`. Splits are loaded and hashed;
they are never regenerated by this runner.

## Inputs and validation

Each fold requires the Phase 5 artifact index and root, Phase 6 split root,
Phase 5 atlas metadata and ROI-mask tensor, and an output root. Before training
the runner validates:

- direction, five-fold integrity and split assignment hash;
- artifact-index hash against the split protocol;
- non-empty source train, source validation and optional target evaluation;
- derivative files for every selected subject;
- source concept and Jacobian files, status, float32 shape and finiteness;
- atlas hash, ROI label order/hash, ROI count and mask payload;
- model-ready input shape, model configuration and non-empty DataLoaders;
- feature-grid masks produced by the canonical nearest/normalize bridge.

No preprocessing, artifact generation, concept fitting or split generation is
available in the runner. Feature-grid preparation does not modify the atlas.

## Training contract

Only `source_train_loader` enters `SourceOnlyTrainer._train_epoch`. Required
fields are `x`, `y`, `c_target`, and `g_bar`. The runner never imports or calls
`build_target_adaptation_loader`; its input-validation record states
`target_adaptation_loader_constructed: false`.

The approved schedule is 20 warm plus 30 full epochs by default, with no early
stopping. The canonical warm multipliers are
`0.1/1.0/0.0/1.0/1.0`; after base weights, effective warm coefficients are
`0.1/1.0/0.0/0.5/0.2`. Full coefficients are
`1.0/1.0/0.1/0.5/0.2`. AdamW, clipping, AMP and resume follow Phase 8.

Source validation loss, accuracy and macro-F1 are calculated at the configured
frequency. Only source macro-F1 can save `checkpoint_best_source_f1.pt`, and
this does not stop training. `checkpoint_last.pt` and periodic checkpoints are
also retained.

Target data are restricted to the immutable labeled `target_evaluation`
partition and no-gradient monitoring. Metrics and predictions use the
`target_monitoring` namespace and the label
`MONITORING ONLY — NOT A TRAINING LOSS`. They cannot affect loss, gradients,
optimizer, scheduler, checkpoint selection, epoch count, resume or tuning.

## Outputs

Runs use:

```text
<output_root>/source_only/<source>_to_<target>/seed_<seed>/fold_<fold>/
```

Each completed fold contains resolved configuration, input validation, atomic
run manifest, checkpoints, history/runtime/reproducibility files, log,
`fold_metrics.json`, and separate source-validation and target-monitoring CSVs
for logical policies `best_source_f1` and `last`.

Prediction CSVs contain subject hash, cohort, true/predicted class and index,
CN/MCI/AD probabilities, direction, method, model label, fold, seed,
checkpoint name/epoch, split and experiment hash. They contain one finite,
normalized row per subject and no MRI tensor.

At direction level, `fold_summary.csv`, `fold_summary.json`, and
`experiment_manifest.json` retain completed, failed and reused folds. Means and
standard deviations are engineering summaries only, not publication inference.

## Resume and reuse

An interrupted fold resumes only from an explicit compatible checkpoint. It
restores the Phase 8 state and preserves experiment/run identity. A completed
fold is reused by default only if its experiment hash, manifest, checkpoints,
metrics and history validate. Incomplete or incompatible directories fail
unless explicit overwrite/recovery is requested.

## CLI

```powershell
python scripts/train.py --config configs/experiments/source_only.yaml `
  --method source_only --source-domain ADNI --target-domain OASIS `
  --fold 0 --seed 42 --artifact-index <index.csv> `
  --artifact-root <cache> --split-root <splits> --roi-masks <roi_masks.pt> `
  --atlas-metadata <atlas_metadata.json> --output-root <runs>
```

Use `--all-folds`, `--all-seeds`, or `--both-directions` for sequential
orchestration. `--dry-run` validates files/manifests and reports workload
without constructing a model or writing checkpoints. `--validate-only` also
constructs model, feature masks and loaders and performs one no-gradient
forward, with no optimizer step. The Phase 8 `--synthetic-smoke` remains
available.

## Limitations

Phase 9 does not implement CORAL, MMD, CDAN, prototypes, pseudo-labels,
confidence gating, domain discriminators, gradient reversal, baselines,
confusion matrices, calibration, concept interventions or publication-level
statistics. No real ADNI/OASIS run was executed during implementation.
