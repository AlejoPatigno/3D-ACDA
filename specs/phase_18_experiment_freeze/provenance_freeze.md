# Phase 18 — Provenance and Identity Freeze

## Purpose

Every future run cell must be reproducible from immutable inputs, an exact resolved configuration, and an authorization record. This document defines the identity boundary only; no real manifest is present or generated by Phase 18 planning.

## Source precedence

1. Active package/configuration contracts and protected Phase 15–17 specifications.
2. The primary non-commented path in `notebooks/archive/training_original.ipynb`.
3. Historical helper definitions and manuscript/prose references, retained only as discrepancy evidence.

A helper, alias, stripped notebook output, or target outcome cannot override an active contract.

## Required identity inputs

A future authorization manifest MUST bind exact content hashes for:

- ordered method inventory and candidate/ablation disposition;
- matrix definition, direction/fold/seed list, and checkpoint policy;
- source split and subject assignment manifests;
- target adaptation and target evaluation assignment manifests, separately and disjointly; their exact bytes MUST be hash-verified before parsing and their parsed subject-identity sets MUST be intersected; aggregate assignment hashes alone are insufficient;
- atlas file/metadata, ROI masks, ROI order, and feature-grid preparation identity;
- concept normalizer, concept-target artifact index, and Jacobian artifact index;
- model architecture/configuration, loss coefficients, training configuration, and resolved method configuration;
- preprocessing configuration and input provenance, without adding preprocessing operations;
- repository source revision, package version, Python/dependency/device environment;
- exact approved command and CLI arguments;
- authorization decision, privacy/data-access record, budget record, and independent review result.

Raw subject identifiers MUST NOT appear in public outputs, logs, or error messages. Stable supplied subject hashes and role-scoped assignment hashes are required; Phase 15's rule that subject hashes are never invented is carried forward.

## Hash rules

- Algorithm: `SHA-256` (`canonical_fixed` repository convention).
- Structured payloads MUST use the versioned profile `phase18.canonical-json.v1`; sorted keys and stable list order alone are insufficient.
- Exact files: SHA-256 over exact bytes before parsing.
- Hash record fields: `name`, `algorithm`, `canonicalization_version`, `value`, `source_path_or_role`, `byte_size`, and `producer_identity`.
- Timestamps MAY be recorded outside hashed scientific identity for operations/audit, but MUST NOT change experiment identity.
- Hashes are recomputed after writes and compared with the recorded index. A mismatch is terminal; rewriting the manifest to match bad bytes is forbidden.

## Canonical JSON profile: `phase18.canonical-json.v1`

Every structured payload that contributes to a Phase 18 identity MUST declare this exact profile and be serialized as UTF-8 bytes with no trailing newline. The profile rules are:

1. Objects are serialized with keys sorted lexicographically by their NFC-normalized Unicode scalar-value sequence; normalization collisions are rejected. Arrays preserve their declared order. Object keys MUST be unique.
2. Strings are NFC-normalized, reject unpaired surrogates, and emit non-ASCII Unicode as raw UTF-8. Only quotation mark, reverse solidus, and control characters U+0000 through U+001F are escaped; the named escapes are used for backspace, form feed, line feed, carriage return, and tab, and all other controls use `\\u00XX` with uppercase hexadecimal digits.
3. Numbers MUST be finite. Negative zero serializes as `0`. Integers use decimal notation without a plus sign or leading zero. Non-integers use the shortest round-trip decimal representation, with lowercase `e`, no leading zero in the exponent, and an explicit minus only for negative values. NaN and infinity are rejected.
4. Separators are exactly `,` between array/object members and `:` between object names and values; no insignificant whitespace is emitted. Booleans and null use the JSON literals `true`, `false`, and `null`.

The conformance vectors below are normative and MUST be checked in with the canonicalizer implementation:

| Input semantic value | Required canonical JSON bytes |
|---|---|
| `{ "b": 1, "a": 2 }` | `{\"a\":2,\"b\":1}` |
| `{ "x": -0.0 }` | `{\"x\":0}` |
| `{ "x": "\\u00e9" }` and `{ "x": "é" }` | `{\"x\":\"é\"}` |
| `[1, 2, 3]` | `[1,2,3]` |
| `{ "x": 1e+06 }` | `{\"x\":1000000}` |

The vector file, canonicalizer implementation identity, and their SHA-256 MUST be included as `canonicalization_conformance_hash` in the real-run gate. If the vectors or their authoritative implementation cannot be supplied and verified, canonicalization remains `unresolved_blocking` and authorization MUST be rejected. The inherited Phase 17 profile may be used only when a payload explicitly declares it; it does not replace the Phase 18 profile.

## Freeze ordering

1. Normalize and inspect source documents/configurations without mutation.
2. Resolve values and classify blockers.
3. Snapshot the ordered matrix and all exact paths/modes intended for a future run.
4. Hash immutable manifests/artifacts and the resolved configuration.
5. Record the synthetic feasibility observation separately from real-data identity.
6. Obtain independent review and human authorization.
7. Only then permit a real-data loader to open configured paths.

## Immutability and reuse

No run may regenerate splits, refit concept normalizers, regenerate concept/Jacobian artifacts, reorder ROIs, silently remap paths, or change preprocessing. Direction identifiers are parser-bound and must be canonical lowercase where required; unknown or legacy aliases fail rather than remap. Resume/reuse is read-only unless the complete identity matches exactly. A completed artifact is not accepted merely because its filename or summary exists; its contents and all referenced hashes must verify. Assignment disjointness is a content-level property checked from hash-verified manifests, not a conclusion from aggregate hashes.

## Current state

Real split, assignment, artifact, environment, command, privacy, and authorization hashes are absent. They are `unresolved_blocking`; no real-run identity can be formed.
